== Tested System
Welche Aufgabe/Problemstellung löst die Anwendung.

=== Login
* provided correct credentials are put in, login is succesfull; otherwise ann error is displayed
* deactivated accounts cannot log in and receive an error message informing about deactivated status
* Passwords do not meet safety standards (missing uppercase, lowercase, numbers, and symbols).

=== Nutzerverwaltung
==== working
* provides a list of all existing users, axcluding the admin
* allows to de-/activate existing accounts
* trying to gain access to Nutzerverwaltung by directly calling the html returns access denied if the user is no admin
* deactivated accounts have active bookings deleted

==== not working
* user details not accessable -  clicking on details of any user account does nothing

=== Konto
==== working
* logout button allows succesfull logout
* shows account details (name, email)
* since uri does not include user_ids no way to adress any other profile than the currently logged in one

=== Registrierung
==== working
* registering with valid input creates a new user account
* invalid credentials include already existing user credentials and wrong patterns for mails and passowrds
* passwords require at leat one upper case letter and hava minimum length of 3
* mails have to be of pattern [name]@[domain]
* invaid inputs return informative error messages pertaining the specific error (except password)
* users have to name a rol the account should have - EventStaff and Landlord accounts are deactivated by default
* new user accounts are activated by default

==== not working
* wrong password patterns all cause the same error messsage "Das Passwort muss mindestens einen Grossbuchstaben enthalten!", regardless of how the pattern is violated

== Event Management

=== Small Events
* Creating, modifying, and deleting small events works as expected.
* Date Input: 
** Users are asked to input a future date, but valid dates sometimes trigger unclear error messages.
** Update: Date validation now works, but the Forward button complicates understanding valid dates.

=== Big Events
* Creating, modifying, and deleting big events works for the most part
* Landlord acceptance and rejection of events works correctly.

=== Booking Events:
* Booking events alongside houses works as intended.
* Only big events should be bookable, which functions as expected.

==== General issues:
* The Forward button causes confusion:
** It advances the timeline, but users are not informed of the exact date they are forwarded to, making it hard to determine valid dates.
** It disrupts functionality across the system, and the purpose of this feature is unclear.
* While creating or modifying an Event, big or small, the interface suggests four pictures can be uploaded, but only one can actually be uploaded.
** Label: “Bilder verbleibend: 4” is misleading.
* When combining events with houses through the radius feature, the created event doesn’t appear under the linked house.
* Ticket count cannot be reduced when modifying events.
* When entering prices under 1€ (e.g., 50 cents), the value is not visible on the event card or details page.

==== Calendar and Map:
* Both features are well-designed and function perfectly.
